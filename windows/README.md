# 윈도우 서버 실습장

네트워크관리사 2급 실기의 Windows Server 2016 설정 문제를 브라우저에서 직접 해 보며 익히는 시뮬레이터의 안내서입니다. 실습 과제 21개와 자유 연습을 담고 있으며, 설정한 결과를 자동으로 채점합니다.

- 실행 파일: `windows/index.html` (브라우저로 열면 바로 동작, 설치 필요 없음)
- [새 문제]를 누를 때마다 IP 주소, 도메인, 이름 같은 값이 새로 정해집니다.
- 완료 표시는 브라우저에만 저장됩니다.
- 실제 Windows의 화면과 동작을 단순화해 흉내 낸 연습용입니다. 실제 시험 화면과 문구, 메뉴 위치가 조금 다를 수 있습니다.

## 서버 구성

```
                    ┌────────────── SERVER (Windows Server 2016, 도메인 컨트롤러) ──────────────┐
                    │  Ethernet0  192.168.100.10/24   GW 192.168.100.1   DNS 127.0.0.1          │
  LAN ──────────────┤  역할: AD DS · DNS · DHCP · IIS(웹, FTP) · 파일 및 저장소 서비스         │
  192.168.100.0/24  │  도메인: netlab.local                                                     │
                    └───────────────────────────────────────────────────────────────────────────┘
```

| 항목 | 기본값 |
|---|---|
| 컴퓨터 이름 | `SERVER` |
| 전체 컴퓨터 이름 | `SERVER.netlab.local` |
| 도메인 | `netlab.local` (NetBIOS 이름 `NETLAB`) |
| Ethernet0 | IP `192.168.100.10`, 마스크 `255.255.255.0`, 게이트웨이 `192.168.100.1`, DNS `127.0.0.1` |
| MAC 주소 | `00-0C-29-3A-5F-12` |
| DNS 영역 | `netlab.local` (Active Directory 통합 주 영역) |
| DHCP | 권한 부여됨, 범위 없음 |
| IIS | `Default Web Site` (http `*:80`, `%SystemDrive%\inetpub\wwwroot`, 시작됨) |
| AD 사용자 | Administrator, Guest(사용 안 함), krbtgt(사용 안 함) |
| 암호 정책 | 기록 24개, 최대 42일, 최소 1일, 최소 길이 7자, 복잡성 사용 |
| 계정 잠금 정책 | 임계값 0 (잠금 기간·원래대로 설정은 적용할 수 없음) |
| C:\ 폴더 | inetpub(ftproot, logs, wwwroot), PerfLogs, Program Files, Program Files (x86), Users, Windows |
| 방화벽 | 세 프로필 모두 켜짐, 인바운드 차단 · 아웃바운드 허용 |
| 원격 데스크톱 | 허용 안 함 |

과제를 고르거나 [처음부터]를 누르면 서버가 이 상태로 돌아간 뒤 과제에 필요한 준비(영역, 범위, 폴더, 사용자 등)가 더해집니다. 예를 들어 TCP/IPv4 과제에서는 Ethernet0이 DHCP(자동) 상태로 바뀌어 시작합니다.

## 화면과 조작법

화면은 두 부분입니다.

- **왼쪽 바탕 화면**: Windows Server처럼 창을 열고 끌고 닫습니다. 아래쪽 작업 표시줄에 열린 창이 표시됩니다.
- **오른쪽 패널**: 현재 과제의 요구 사항, [채점하기], [풀이 보기], [새 문제], [처음부터], 그리고 과제 목록과 실행 명령어 표가 있습니다.

| 동작 | 방법 |
|---|---|
| 프로그램 열기 | 바탕 화면 아이콘 두 번 클릭 (터치 화면은 한 번 누르기) |
| 시작 메뉴 | 작업 표시줄 왼쪽 Windows 단추 |
| 실행 창(Win+R) | 시작 단추 **오른쪽 클릭** → 실행(R) |
| 네트워크 연결 | 시작 단추 오른쪽 클릭 → 네트워크 연결(W) |
| 상황에 맞는 메뉴 | 트리나 목록 항목을 오른쪽 클릭, 또는 창 메뉴 줄의 **동작(A)** |
| 하위 메뉴 | `▸` 표시가 있는 항목(예: 새로 만들기)에 마우스를 올리거나 누르기 |
| 속성 열기 | 목록 항목 두 번 클릭 |
| 트리 펼치기 | `▷` 누르기 또는 항목 두 번 클릭 |
| 창 이동 | 제목 표시줄 끌기 |
| 창 최소화 · 다시 열기 | `—` 단추, 작업 표시줄 단추 |
| 대화 상자 확인 | `Enter` (기본 단추), 닫기는 `Esc` |
| IP 주소 칸 | 숫자 3자리를 치거나 `.`을 누르면 다음 칸으로 넘어갑니다. `Backspace`로 앞 칸으로 돌아갑니다. 주소 전체를 붙여 넣어도 됩니다. |
| 채점 | 설정을 마친 뒤 패널의 **[채점하기]**. 틀린 항목 아래에 **기대 값**과 **현재 값**이 나란히 나옵니다. |

> **가장 흔한 실수**: 실제 Windows처럼 바깥쪽 창의 [확인]까지 눌러야 저장됩니다.
> TCP/IPv4 속성에서 [확인]을 눌러도 `Ethernet0 속성` 창에서 [확인]을 누르지 않으면 적용되지 않습니다.
> 시스템 속성, 공유 권한 → 고급 공유, 영역 속성도 마찬가지입니다.

## 도구 여는 법

시험에서는 보통 **서버 관리자 → 도구(T)** 로 엽니다. 같은 도구를 여러 경로로 열 수 있습니다.

| 도구 | 실행 명령 | 다른 경로 |
|---|---|---|
| 네트워크 연결 | `ncpa.cpl` | 시작 단추 오른쪽 클릭 → 네트워크 연결, 서버 관리자 → 로컬 서버 → Ethernet0 |
| DNS 관리자 | `dnsmgmt.msc` | 서버 관리자 → 도구 → DNS |
| DHCP | `dhcpmgmt.msc` | 서버 관리자 → 도구 → DHCP |
| IIS(인터넷 정보 서비스) 관리자 | `inetmgr` | 서버 관리자 → 도구 |
| Active Directory 사용자 및 컴퓨터 | `dsa.msc` | 서버 관리자 → 도구 |
| 로컬 보안 정책 | `secpol.msc` | 서버 관리자 → 도구 |
| 그룹 정책 관리 | `gpmc.msc` | 서버 관리자 → 도구 → Default Domain Policy 오른쪽 클릭 → 편집 |
| 고급 보안이 포함된 Windows 방화벽 | `wf.msc` | 서버 관리자 → 도구, 서버 관리자 → 로컬 서버 → Windows 방화벽 |
| 시스템 속성 | `sysdm.cpl` | 시작 단추 오른쪽 클릭 → 시스템, 서버 관리자 → 로컬 서버 → 컴퓨터 이름 / 원격 데스크톱 |
| 명령 프롬프트 | `cmd` | 바탕 화면 아이콘, 시작 단추 오른쪽 클릭 → 명령 프롬프트 |
| 파일 탐색기 | `explorer` | 바탕 화면 **내 PC** |
| 서버 관리자 | `servermanager` | 바탕 화면 아이콘 |

실행 창에서는 `.exe`를 붙여도 되고 대소문자를 가리지 않습니다. 없는 이름을 치면 "찾을 수 없습니다" 오류가 나옵니다.

## 시험에 자주 나오는 기본 지식

### 접두사와 서브넷 마스크

과제에서 마스크를 `/26`처럼 접두사로 주면 직접 바꿔 입력해야 합니다.

| 접두사 | 서브넷 마스크 | 블록 크기 | 사용 가능한 호스트 |
|---|---|---|---|
| /16 | 255.255.0.0 | 65,536 | 65,534 |
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

IP 주소를 먼저 넣고 서브넷 마스크 칸을 누르면 Windows처럼 **클래스 기본 마스크**(10.x → 255.0.0.0, 172.16~31.x → 255.255.0.0, 192.168.x → 255.255.255.0)가 자동으로 채워집니다. 과제의 마스크와 다르면 지우고 다시 입력하세요.

### DNS 레코드

| 레코드 | 메뉴 이름 | 뜻 | 입력 예 |
|---|---|---|---|
| A | 새 호스트(A 또는 AAAA) | 이름 → IPv4 주소 | 이름 `www`, IP `192.168.1.10` |
| CNAME | 새 별칭(CNAME) | 이름 → 다른 이름 | 별칭 `web`, 대상 `www.example.com` |
| MX | 새 메일 교환기(MX) | 도메인의 메일 서버 | 호스트 칸 비움, 메일 서버 `mail.example.com`, 우선 순위 `10` |
| PTR | 새 포인터(PTR) | IP 주소 → 이름 (역방향) | `192.168.1.10` → `www.example.com` |
| NS | (영역 속성 → 이름 서버) | 영역의 이름 서버 | 영역을 만들면 자동 |
| SOA | (영역 속성 → SOA) | 영역의 권한 정보 | 영역을 만들면 자동 |

- 역방향 영역 이름은 네트워크 ID를 거꾸로 쓰고 `in-addr.arpa`를 붙입니다. `192.168.10` → `10.168.192.in-addr.arpa`
- MX 우선 순위는 **숫자가 작을수록** 먼저 쓰입니다.
- 동적 업데이트 종류: **없음**, **비보안 및 보안**, **보안**(AD 통합 영역만)

### SOA 시간 값

| 항목 | 뜻 | 기본값 |
|---|---|---|
| 새로 고침 간격 | 보조 서버가 주 서버에 변경 여부를 묻는 주기 | 15분 |
| 다시 시도 간격 | 새로 고침에 실패했을 때 다시 묻는 주기 | 10분 |
| 다음 날짜 이후에 만료 | 주 서버와 연락이 끊긴 보조 서버가 영역을 버리는 시간 | 1일 |
| 최소(기본값) TTL | 레코드를 캐시에 두는 기본 시간 | 1시간 |

### DHCP 옵션

| 옵션 | 이름 | 값 |
|---|---|---|
| 003 | 라우터 | 기본 게이트웨이 IP |
| 006 | DNS 서버 | DNS 서버 IP (여러 개, 순서 중요) |
| 015 | DNS 도메인 이름 | 문자열 (예: `netlab.local`) |
| 044 | WINS/NBNS 서버 | WINS 서버 IP |
| 004 | 시간 서버 | 시간 서버 IP |

### 권한

| 공유 권한 | 포함하는 권한 |
|---|---|
| 모든 권한 | 변경 + 읽기 + 권한 변경 |
| 변경 | 읽기 + 쓰기·삭제 |
| 읽기 | 보기·열기 |

| NTFS 권한 | 포함하는 권한 |
|---|---|
| 모든 권한 | 수정 + 권한 변경 + 소유권 가져오기 |
| 수정 | 읽기 및 실행 + 폴더 내용 보기 + 읽기 + 쓰기 + 삭제 |
| 읽기 및 실행 | 폴더 내용 보기 + 읽기 + 실행 |

- 상위 권한을 선택하면 하위 권한이 함께 선택됩니다. 하위 권한을 해제하면 그것을 포함하는 상위 권한도 해제됩니다.
- **거부는 허용보다 우선**합니다.
- 공유 권한과 NTFS 권한이 함께 걸리면 네트워크 접속 시 **둘 중 더 엄격한 쪽**이 적용됩니다.
- 공유 이름 끝에 `$`를 붙이면 네트워크 목록에 보이지 않는 **숨김 공유**가 됩니다.

### AD 그룹 범위

| 범위 | 구성원으로 넣을 수 있는 것 | 쓰이는 곳 |
|---|---|---|
| 도메인 로컬 | 모든 도메인의 사용자·그룹 | 자기 도메인의 리소스 권한 |
| 글로벌 | 같은 도메인의 사용자·그룹 | 모든 도메인의 리소스 권한 |
| 유니버설 | 포리스트의 모든 사용자·그룹 | 포리스트 전체 |

그룹 종류: **보안**(권한 부여 가능), **배포**(메일 목록 용도, 권한 부여 불가)

## 실습

과제 목록에서 고르면 문제가 나옵니다. 각 과제의 값은 [새 문제]를 누를 때마다 바뀌므로 아래 예시의 숫자는 참고용입니다. 오른쪽 패널의 [풀이 보기]를 누르면 그 문제의 값에 맞춘 순서가 나옵니다.

### 1 · TCP/IPv4 고정 IP 설정

**상황**: Ethernet0이 DHCP로 주소를 받고 있습니다.
**요구**: IP 주소, 서브넷 마스크(접두사로 나올 수 있음), 기본 게이트웨이, 기본 설정 DNS, 보조 DNS

1. 시작 단추 오른쪽 클릭 → **네트워크 연결** (또는 실행 창에 `ncpa.cpl`)
2. **Ethernet0** 오른쪽 클릭 → **속성**
3. **인터넷 프로토콜 버전 4(TCP/IPv4)** 선택 → **속성** (두 번 클릭해도 됨)
4. **다음 IP 주소 사용** 선택 → IP 주소, 서브넷 마스크, 기본 게이트웨이 입력
5. **다음 DNS 서버 주소 사용** (IP를 고정하면 자동으로 선택됨) → 기본 설정 DNS, 보조 DNS 입력
6. [확인] → `Ethernet0 속성`에서도 [확인]

알아 둘 점

- 게이트웨이가 IP·마스크와 다른 서브넷이면 "같은 네트워크 세그먼트에 있지 않습니다" 경고가 나옵니다. 계산을 다시 확인하세요.
- 마스크가 비어 있으면 "서브넷 마스크 항목이 없습니다" 오류가 나옵니다.
- 확인은 [채점하기] 또는 명령 프롬프트의 `ipconfig /all`로 할 수 있습니다.

### 2 · 고급 TCP/IP · IPv6 해제

**상황**: Ethernet0은 `192.168.100.10/24`입니다. 기존 주소는 그대로 둡니다.
**요구**: 두 번째 IP 주소 추가, 보조 DNS 추가, 연결별 DNS 접미사, NetBIOS 사용 안 함, IPv6 해제

1. 네트워크 연결 → Ethernet0 속성
2. **인터넷 프로토콜 버전 6(TCP/IPv6)** 확인란 해제
3. IPv4 → 속성 → 보조 DNS 서버 입력 → **고급(V)...**
4. **IP 설정** 탭 → IP 주소의 [추가] → 주소와 마스크 → [추가]
5. **DNS** 탭 → **이 연결의 DNS 접미사** 입력
6. **WINS** 탭 → **TCP/IP에서 NetBIOS 사용 안 함**
7. 고급 창 [확인] → IPv4 창 [확인] → 어댑터 창 [확인]

알아 둘 점

- 첫 번째 IP가 기본 주소입니다. 기존 주소를 지우거나 순서를 바꾸면 틀립니다.
- DNS 탭에서도 DNS 서버를 추가하고 ↑↓로 순서를 바꿀 수 있습니다.

### 3 · 정방향 조회 영역 만들기

**요구**: 영역 이름, 주 영역, AD에 저장하지 않음, 영역 파일 이름(기본값 또는 지정값), 동적 업데이트

1. 서버 관리자 → 도구 → **DNS**
2. SERVER → **정방향 조회 영역** 오른쪽 클릭 → **새 영역**
3. 시작 화면 [다음]
4. **영역 형식**: 주 영역, **Active Directory에 영역 저장** 확인란 해제
5. **영역 이름**: 예 `practice.com`
6. **영역 파일**: 다음 이름으로 새 파일 만들기 (기본값 `practice.com.dns`, 과제가 지정하면 바꿈)
7. **동적 업데이트**: 과제에 맞게 선택
8. [마침]

알아 둘 점

- AD에 저장을 선택하면 영역 파일 화면 대신 복제 범위 화면이 나오고, 보안 동적 업데이트를 고를 수 있게 됩니다.
- 보조 영역이나 스텁 영역은 마스터 DNS 서버 IP를 지정하는 화면이 추가됩니다.
- 이름이 같은 영역이 이미 있으면 만들 수 없습니다.

### 4 · 호스트·별칭·메일 교환기 레코드

**상황**: 영역이 이미 만들어져 있습니다.
**요구**: A 레코드 `www`, `ftp`, `mail`, CNAME 별칭, MX 레코드(우선 순위)

1. DNS 관리자 → 정방향 조회 영역 → 해당 영역 선택
2. 영역 오른쪽 클릭 → **새 호스트(A 또는 AAAA)**
3. 이름 `www`, IP 주소 입력 → **[호스트 추가]** → "만들었습니다" 확인
4. 창이 닫히지 않으므로 `ftp`, `mail`도 이어서 추가 → [완료]
5. 영역 오른쪽 클릭 → **새 별칭(CNAME)** → 별칭 이름, **대상 호스트의 FQDN** (예 `www.practice.com`) → [확인]
6. 영역 오른쪽 클릭 → **새 메일 교환기(MX)** → 호스트 칸은 비움 → 메일 서버 FQDN, 우선 순위 → [확인]

알아 둘 점

- 대상 호스트는 `www`만 쓰지 말고 **FQDN 전체**를 씁니다.
- MX의 호스트 칸을 비우면 `(같은 부모 폴더)`, 즉 도메인 자체의 메일 서버가 됩니다.
- 이미 A 레코드가 있는 이름으로는 별칭을 만들 수 없습니다.
- 레코드를 두 번 클릭하면 IP나 대상을 고칠 수 있습니다.

### 5 · 역방향 조회 영역과 PTR 레코드

**상황**: 정방향 영역이 있습니다.
**요구**: 역방향 영역(주 영역, 영역 파일), A 레코드, 그 IP의 PTR 레코드

1. DNS 관리자 → **역방향 조회 영역** 오른쪽 클릭 → 새 영역
2. 주 영역, AD 저장 해제 → **IPv4 역방향 조회 영역**
3. **네트워크 ID**에 앞 세 옥텟 입력 (예 `192.168.27`) → 영역 이름이 `27.168.192.in-addr.arpa`로 자동 생성
4. 영역 파일 → 동적 업데이트 → [마침]
5. 정방향 영역 → 새 호스트 → 이름, IP 입력, **연결된 PTR(포인터) 레코드 만들기** 선택 → [호스트 추가]

알아 둘 점

- 역방향 영역보다 호스트를 먼저 만들면 "참조된 역방향 조회 영역을 찾을 수 없습니다" 경고가 나오고 PTR은 만들어지지 않습니다. 이때는 역방향 영역에서 **새 포인터(PTR)** 로 직접 만들면 됩니다.
- 명령 프롬프트에서 `nslookup IP주소`로 PTR을 확인할 수 있습니다.

### 6 · SOA · 영역 전송 · 동적 업데이트

**요구**: 새로 고침 간격, 다시 시도 간격, 만료, 최소 TTL, 영역 전송 대상 서버, 동적 업데이트

1. DNS 관리자 → 영역 오른쪽 클릭 → **속성**
2. **권한 있는 영역 시작(SOA)** 탭 → 각 항목의 **숫자와 단위**(초/분/시간/일)를 맞춤
3. **영역 전송** 탭 → **영역 전송 허용** → **다음 서버로만** → [편집] → IP 입력 → [추가] → [확인]
4. **일반** 탭 → 동적 업데이트 선택
5. [확인]

알아 둘 점

- 채점은 초 단위로 환산해 비교하므로 `1시간`과 `60분`은 같습니다.
- 파일 기반 주 영역은 기본으로 "이름 서버 탭에 나열된 서버로만" 전송이 허용되어 있습니다.
- [증가] 단추로 일련 번호를 올릴 수 있습니다.

### 7 · 전달자와 조건부 전달자

**요구**: 전달자 1·2순위, 루트 힌트 사용 안 함, 조건부 전달자

1. DNS 관리자 → **SERVER** 오른쪽 클릭 → **속성** → **전달자** 탭 → [편집]
2. IP를 순서대로 추가 (위로/아래로로 순서 조정) → [확인]
3. **사용할 수 있는 전달자가 없을 경우 루트 힌트 사용** 해제 → [확인]
4. **조건부 전달자** 폴더 오른쪽 클릭 → **새 조건부 전달자** → DNS 도메인, [편집]으로 마스터 서버 IP → [확인]

알아 둘 점

- **고급** 탭의 "재귀 사용 안 함"을 선택하면 전달자도 쓰지 않게 됩니다.
- 조건부 전달자는 지정한 도메인에 대해 서버 수준 전달자보다 우선합니다.

### 8 · DHCP 범위 만들기

**요구**: 범위 이름, 시작·끝 IP, 마스크, 제외 범위, 임대 기간, 라우터, DNS 서버·부모 도메인, 활성화. 문제의 절반은 DHCP 서버가 **권한 부여되지 않은 상태**로 시작해 권한 부여도 채점합니다.

1. 서버 관리자 → 도구 → **DHCP**
2. 서버 → **IPv4** 오른쪽 클릭 → **새 범위**
3. **범위 이름**: 이름(설명은 선택)
4. **IP 주소 범위**: 시작 IP, 끝 IP, **길이** 또는 **서브넷 마스크** (서로 연동됨)
5. **제외 및 지연 추가**: 시작·끝 IP → [추가] (한 주소만 제외하면 시작 IP만)
6. **임대 기간**: 일·시간·분 (기본 8일)
7. **DHCP 옵션 구성**: "예, 지금 이 옵션을 구성합니다"
8. **라우터(기본 게이트웨이)**: IP → [추가]
9. **도메인 이름 및 DNS 서버**: 부모 도메인 입력, 기본으로 들어 있는 서버 IP는 필요 없으면 [제거], DNS IP → [추가]
10. **WINS 서버**: 보통 비워 둠
11. **범위 활성화**: "예, 지금 이 범위를 활성화합니다"
12. [마침]
13. (권한이 없을 때) 서버 `server.netlab.local` 오른쪽 클릭 → **권한 부여** → IPv4 아이콘이 초록색으로 바뀜

알아 둘 점

- 권한이 부여되지 않은 DHCP 서버는 범위가 활성이어도 주소를 나눠 주지 않습니다. 실제 시험에서도 **권한 부여**와 **범위 활성화**를 따로 확인하세요.
- 시작·끝 IP는 같은 서브넷에 있어야 하며 시작이 끝보다 작아야 합니다.
- 제외 범위는 범위 안에 있어야 합니다.
- "아니요, 나중에 구성합니다"를 고르면 옵션 화면을 건너뛰고 범위가 **비활성**으로 만들어집니다. 나중에 범위 오른쪽 클릭 → **활성화**.
- 비활성 범위는 트리 아이콘에 빨간 화살표가 붙습니다.
- DNS 서버 목록의 **순서**도 채점합니다.

### 9 · 예약 · 제외 · 범위 옵션

**상황**: 범위 `LAN` (x.x.x.100 ~ x.x.x.200)이 있습니다.
**요구**: 예약(이름·IP·MAC), 제외 범위 추가, 006 DNS 서버 추가, 015 도메인 이름 변경, 임대 기간 변경

1. DHCP → IPv4 → 범위 펼치기
2. **예약** 오른쪽 클릭 → **새 예약** → 예약 이름, IP, MAC 주소 → [추가] → [닫기]
3. **주소 풀** 오른쪽 클릭 → **새 제외 범위** → 시작·끝 IP → [추가] → [닫기]
4. **범위 옵션** 오른쪽 클릭 → **옵션 구성** → `006 DNS 서버` 선택 → IP [추가] → `015 DNS 도메인 이름` 선택 → 문자열 수정 → [확인]
5. 범위 오른쪽 클릭 → **속성** → 임대 기간 → [확인]

알아 둘 점

- MAC 주소는 `00-11-22-33-44-55`, `001122334455`, `00:11:22:33:44:55` 어느 형식이든 됩니다.
- 예약 IP는 범위의 서브넷 안이어야 하고 같은 IP나 MAC을 두 번 예약할 수 없습니다.
- 서버 전체에 적용하려면 **서버 옵션**에서, 이 범위에만 적용하려면 **범위 옵션**에서 설정합니다.

### 10 · 웹 사이트 추가

**요구**: 사이트 이름, 실제 경로, 응용 프로그램 풀(기본값), 바인딩(IP·포트·호스트 이름), 시작 상태. 변형 문제에서는 Default Web Site 중지 또는 제거가 추가됩니다.

1. 서버 관리자 → 도구 → **IIS(인터넷 정보 서비스) 관리자**
2. SERVER → **사이트** 오른쪽 클릭 → **웹 사이트 추가**
3. 사이트 이름 (응용 프로그램 풀이 같은 이름으로 자동 생성)
4. 실제 경로: 직접 입력하거나 [...]로 폴더 선택
5. 바인딩: 종류 `http`, IP 주소 목록에서 `192.168.100.10`, 포트, 호스트 이름
6. **즉시 웹 사이트 시작** → [확인]

알아 둘 점

- 다른 시작된 사이트와 **IP·포트·호스트 이름이 모두 겹치면** "한 사이트만 시작할 수 있습니다" 경고가 나오고 새 사이트는 중지된 채 만들어집니다.
- 포트 80을 그대로 쓰려면 Default Web Site를 선택해 오른쪽 작업 창에서 **중지**하거나 오른쪽 클릭 → **제거**한 뒤 새 사이트를 **시작**합니다. 포트나 호스트 이름을 달리 지정해도 됩니다.
- 응용 프로그램 풀은 사이트 이름과 같은 이름으로 자동으로 만들어집니다.
- 바인딩은 사이트 선택 → 작업 창 **바인딩...** 에서 추가·편집·제거합니다.
- 사이트 이름·경로 변경은 **기본 설정...** 입니다.

### 11 · 기본 문서 · 디렉터리 검색 · 연결 제한

**요구**: 기본 문서 추가와 맨 위로 이동, `iisstart.htm` 제거, 디렉터리 검색 사용, 연결 시간 제한, 연결 수 제한

1. IIS 관리자 → Default Web Site 선택 → 가운데 기능 보기
2. **기본 문서** 두 번 클릭 → 작업 창 **추가...** → 이름 입력 (새 항목은 맨 위에 들어감)
3. 목록에서 `iisstart.htm` 선택 → **제거** → 예
4. 왼쪽 위 `◀ ... 홈` → **디렉터리 검색** 두 번 클릭 → 작업 창 **사용**
5. 작업 창 **구성 › 제한...** → 연결 시간 제한(초), **연결 수 제한** 확인란 선택 후 값 입력 → [확인]

알아 둘 점

- 기본 문서는 위에서부터 차례로 찾습니다. **위로 이동 / 아래로 이동**으로 순서를 바꿉니다.
- 디렉터리 검색의 표시 항목(시간, 크기, 확장명, 날짜) 확인란은 [적용]을 눌러야 저장됩니다.
- 연결 시간 제한의 기본값은 120초입니다.

### 12 · IP 주소 제한과 인증

**요구**: 지정되지 않은 클라이언트 거부, 허용 항목(IP 범위), 거부 항목(특정 IP), 익명 인증 사용 안 함, 기본 인증 사용

1. Default Web Site → **IP 주소 및 도메인 제한** 두 번 클릭
2. 작업 창 **허용 항목 추가...** → IP 주소 범위, 마스크 또는 접두사(`255.255.255.0` 또는 `24`) → [확인]
3. **거부 항목 추가...** → 특정 IP 주소 → [확인]
4. **기능 설정 편집...** → 지정되지 않은 클라이언트에 대한 액세스: **거부** → [확인]
5. `◀ 홈` → **인증** → 익명 인증 선택 → **사용 안 함**, 기본 인증 선택 → **사용**

### 13 · FTP 사이트 추가

**요구**: 사이트 이름·경로, 바인딩(IP·포트·자동 시작), SSL 없음, 인증 방식, 권한 부여 규칙

1. IIS 관리자 → **사이트** 오른쪽 클릭 → **FTP 사이트 추가**
2. **사이트 정보**: FTP 사이트 이름, 실제 경로
3. **바인딩 및 SSL 설정**: IP 주소, 포트(기본 21), 자동으로 FTP 사이트 시작, **SSL 없음**
4. **인증 및 권한 부여 정보**: 인증(익명/기본), 액세스 허용(모든 사용자/익명 사용자/지정한 역할/지정한 사용자), 사용 권한(읽기/쓰기)
5. [마침]

알아 둘 점

- SSL을 허용·필요로 하면 SSL 인증서를 골라야 다음으로 넘어갑니다.
- 만든 뒤에는 FTP 사이트를 선택해 **FTP 인증**, **FTP 권한 부여 규칙**, **FTP SSL 설정** 기능에서 고칠 수 있습니다.

### 14 · 조직 구성 단위와 사용자 만들기

**요구**: 도메인 바로 아래 OU, 그 안의 사용자(성·이름·로그온 이름(UPN)·Windows 2000 이전 로그온 이름·암호), 계정 옵션

1. 서버 관리자 → 도구 → **Active Directory 사용자 및 컴퓨터**
2. `netlab.local` 오른쪽 클릭 → 새로 만들기 ▸ **조직 구성 단위** → 이름 → [확인]
3. 만든 OU 오른쪽 클릭 → 새로 만들기 ▸ **사용자**
4. 성, 이름 (전체 이름 자동) → **사용자 로그온 이름** (`이름@netlab.local`이 UPN, 아래 칸 `NETLAB\이름`은 Windows 2000 이전 버전 이름으로 자동 입력) → [다음]
5. 암호, 암호 확인 → 계정 옵션 확인란 → [다음] → [마침]

계정 옵션

| 확인란 | 기본값 | 함께 쓸 수 없는 것 |
|---|---|---|
| 다음 로그온할 때 반드시 암호 변경 | **선택** | 암호 사용 기간 제한 없음, 사용자가 암호를 변경할 수 없음 |
| 사용자가 암호를 변경할 수 없음 | 해제 | 다음 로그온 시 변경 |
| 암호 사용 기간 제한 없음 | 해제 | 다음 로그온 시 변경 (선택하면 자동 해제됨) |
| 계정 사용 안 함 | 해제 | — |

알아 둘 점

- 암호가 정책(기본: 7자 이상, 대문자·소문자·숫자·특수 문자 중 세 가지, 로그온 이름 포함 금지)을 만족하지 않으면 [마침]에서 오류가 나옵니다. `P@ssw0rd` 같은 형태를 쓰세요.
- 로그온 이름이 이미 있으면 만들 수 없습니다.
- 새로 만든 OU는 기본으로 **실수로 삭제되지 않도록 보호**되어 바로 삭제되지 않습니다. OU 속성 → 개체 탭에서 해제할 수 있습니다.

### 15 · 그룹 만들기와 구성원 추가

**상황**: OU 안에 사용자 두 명이 있습니다.
**요구**: OU 안에 그룹(범위·종류), 두 사용자를 구성원으로, 사용자 전화 번호

1. OU 오른쪽 클릭 → 새로 만들기 ▸ **그룹** → 그룹 이름, 그룹 범위, 그룹 종류 → [확인]
2. 사용자 오른쪽 클릭 → **그룹에 추가...** → 그룹 이름 입력 → **[이름 확인]** → [확인]
   또는 그룹 속성 → **구성원** 탭 → [추가] → 사용자 이름(여러 명은 `;`로 구분) → [확인]
3. 사용자 두 번 클릭 → **일반** 탭 → 전화 번호 → [확인]

알아 둘 점

- 이름은 일부만 입력해도 하나로 정해지면 [이름 확인]이 완성해 줍니다.
- 사용자 속성의 **소속 그룹** 탭에서도 그룹을 추가·제거할 수 있습니다. 주 그룹 Domain Users는 제거할 수 없습니다.

### 16 · 암호 정책과 계정 잠금 정책

**요구**: 최소 암호 길이, 최대·최소 암호 사용 기간, 최근 암호 기억, 복잡성, 계정 잠금 세 항목, 로그온 이벤트 감사

1. 서버 관리자 → 도구 → **로컬 보안 정책**
2. 계정 정책 → **암호 정책** → 항목 두 번 클릭 → 값 → [확인]
3. 계정 정책 → **계정 잠금 정책** → **계정 잠금 임계값**부터 설정
4. "제안된 값 변경" 창에서 [확인] (잠금 기간과 원래대로 설정이 30분으로 정해짐)
5. 계정 잠금 기간, 다음 시간 후 계정 잠금 수를 원래대로 설정을 과제 값으로 수정
6. 로컬 정책 → **감사 정책** → 로그온 이벤트 감사 → 성공, 실패 → [확인]

같은 설정을 **그룹 정책 관리**에서도 할 수 있습니다. 실제 도메인 컨트롤러에서는 이쪽이 도메인 전체의 암호 정책입니다.

1. 실행 창에 `gpmc.msc` (또는 서버 관리자 → 도구 → 그룹 정책 관리)
2. 포리스트 → 도메인 → `netlab.local` → **Default Domain Policy** 오른쪽 클릭 → **편집**
3. 그룹 정책 관리 편집기: 컴퓨터 구성 → 정책 → Windows 설정 → 보안 설정 → 계정 정책 / 로컬 정책

| 정책 | 범위 | 기본값 |
|---|---|---|
| 최근 암호 기억 | 0~24개 | 24개 |
| 최대 암호 사용 기간 | 0~999일 (0 = 만료 없음) | 42일 |
| 최소 암호 길이 | 0~14자 | 7자 |
| 최소 암호 사용 기간 | 0~998일 | 1일 |
| 암호는 복잡성을 만족해야 함 | 사용/사용 안 함 | 사용 |
| 계정 잠금 임계값 | 0~999번 (0 = 잠그지 않음) | 0번 |
| 계정 잠금 기간 | 0~99999분 (0 = 관리자가 풀 때까지) | 적용할 수 없음 |
| 다음 시간 후 계정 잠금 수를 원래대로 설정 | 1~99999분 | 적용할 수 없음 |

알아 둘 점

- 최소 암호 사용 기간은 최대 암호 사용 기간보다 작아야 합니다.
- 잠금 수를 원래대로 설정하는 시간은 잠금 기간보다 클 수 없습니다. 크게 넣으면 잠금 기간도 같이 바꾸자는 제안 창이 나옵니다.
- 임계값이 0이면 잠금 기간과 원래대로 설정은 바꿀 수 없습니다.
- 여기서 바꾼 암호 정책은 바로 AD 사용자 암호 검사에 반영됩니다.

### 17 · 폴더 공유와 공유 권한

**상황**: `C:\` 아래에 공유할 폴더가 있습니다.
**요구**: 공유 이름(숨김 공유일 수 있음), 동시 사용자 수 제한, 설명, Everyone 읽기만, Administrators 모든 권한

1. 바탕 화면 **내 PC** → 로컬 디스크 (C:) → 폴더 오른쪽 클릭 → **속성**
2. **공유** 탭 → **고급 공유...**
3. **선택한 폴더 공유** → 공유 이름, 동시 사용자 수 제한, 설명
4. **권한** → Everyone은 읽기 허용만 둠 → [추가] → `Administrators` → [이름 확인] → [확인] → **모든 권한** 허용
5. 권한 창 [확인] → 고급 공유 [확인] → 속성 창 [확인]

알아 둘 점

- 공유 이름은 공유를 처음 만들 때만 정할 수 있습니다. 바꾸려면 공유를 해제한 뒤 다시 만드세요.
- 서버의 동시 사용자 수 기본값은 16777216입니다.
- 공유된 폴더 아이콘에는 사람 모양이 붙습니다. 명령 프롬프트의 `net share`로도 확인할 수 있습니다.

### 18 · NTFS 보안 권한

**요구**: 사용자에게 수정 허용(모든 권한은 아님), Users 그룹에 쓰기 거부

1. 폴더 속성 → **보안** 탭 → **편집...**
2. [추가] → 사용자 로그온 이름 → [이름 확인] → [확인]
3. 추가한 사용자 선택 → **수정** 허용
4. **Users** 선택 → **쓰기** 거부
5. [확인] → 거부 경고에 [예] → 속성 창 [확인]

알아 둘 점

- 회색으로 선택된 허용 확인란은 부모 폴더에서 상속된 권한이라 해제할 수 없습니다. 거부로 막을 수는 있습니다.
- 상속된 항목(Administrators, SYSTEM, Users, CREATOR OWNER)은 제거할 수 없습니다.
- 새로 추가한 사용자에게는 기본으로 읽기 및 실행·폴더 내용 보기·읽기가 허용됩니다.

### 19 · 인바운드 규칙 만들기

**요구**: 규칙 이름, 프로토콜과 포트, 작업, 프로필(공용 제외), ICMPv4 에코 요청 규칙 사용

1. 서버 관리자 → 도구 → **고급 보안이 포함된 Windows 방화벽**
2. **인바운드 규칙** 오른쪽 클릭 → **새 규칙...**
3. 규칙 종류: **포트**
4. 프로토콜 및 포트: TCP 또는 UDP, **특정 로컬 포트** (예 `8080`, `80, 443`, `5000-5010`)
5. 작업: 연결 허용 / 보안 연결만 허용 / 연결 차단
6. 프로필: 도메인, 개인, 공용 중 선택
7. 이름 → [마침]
8. 목록에서 **파일 및 프린터 공유(에코 요청 - ICMPv4-In)** 오른쪽 클릭 → **규칙 사용**

알아 둘 점

- 규칙 종류 **미리 정의됨**을 고르면 파일 및 프린터 공유, 원격 데스크톱 같은 그룹 규칙을 한꺼번에 켤 수 있습니다.
- 사용 중인 규칙은 초록색 체크, 사용 안 함은 회색, 차단은 빨간색 아이콘입니다.
- 규칙을 두 번 클릭하면 일반·프로토콜 및 포트·고급(프로필) 탭에서 고칠 수 있습니다.
- 맨 위 노드 → 속성에서 프로필별 방화벽 켜기/끄기, 기본 인바운드·아웃바운드 동작을 바꿉니다.

### 20 · 원격 데스크톱 허용과 컴퓨터 이름

**요구**: 원격 연결 허용, 네트워크 수준 인증(NLA) 확인란, 원격 데스크톱 사용자 추가, 원격 지원 해제, 컴퓨터 이름 변경

1. 실행 창에 `sysdm.cpl`
2. **컴퓨터 이름** 탭 → [변경...] → 새 컴퓨터 이름 → [확인] → 다시 시작 안내 [확인]
3. **원격** 탭 → **이 컴퓨터에 대한 원격 연결 허용** → NLA 확인란을 과제에 맞게
4. [사용자 선택...] → [추가] → 사용자 이름 → [확인] → [확인]
5. 시스템 속성 [확인]

알아 둘 점

- 컴퓨터 이름은 15자 이하, 문자·숫자·하이픈만 됩니다. 변경 내용은 다시 시작한 뒤 적용되므로 "다시 시작 대기"로 채점합니다.
- 원격 연결을 허용하면 방화벽의 **원격 데스크톱** 규칙이 자동으로 켜집니다.
- 이 서버는 도메인 컨트롤러라 작업 그룹으로 바꿀 수 없습니다.

### 21 · 네트워크 명령어

**요구**: 무작위로 나온 네 가지 작업에 맞는 명령을 명령 프롬프트에서 실행

1. 바탕 화면 **명령 프롬프트** (또는 실행 창에 `cmd`)
2. 명령 입력 → `Enter`

| 작업 | 명령 |
|---|---|
| DNS 확인자 캐시 비우기 | `ipconfig /flushdns` |
| DNS 확인자 캐시 내용 보기 | `ipconfig /displaydns` |
| MAC·DNS까지 자세한 IP 구성 | `ipconfig /all` |
| DNS에 이름 다시 등록 | `ipconfig /registerdns` |
| 라우팅 테이블 | `route print` 또는 `netstat -r` |
| 모든 연결·수신 포트를 숫자로 | `netstat -an` |
| ARP 캐시 | `arp -a` |
| 컴퓨터 이름 | `hostname` |
| 공유 폴더 목록 | `net share` |
| 에코 요청 횟수 지정 | `ping -n 6 8.8.8.8` |
| 경로 추적 | `tracert 8.8.8.8` |
| 이름의 IP 질의 | `nslookup www.google.com` |

옵션은 `-`와 `/` 둘 다 됩니다. `↑` `↓`로 이전 명령을 다시 불러옵니다.

### 자유 연습

채점 없이 모든 도구를 마음대로 다뤄 봅니다. 여러 과제를 섞어 서버 하나를 처음부터 끝까지 구성해 보는 데 좋습니다. 예를 들어 DNS 영역과 A 레코드를 만든 뒤 `nslookup`과 `ping`으로 이름이 풀리는지 확인할 수 있습니다.

## 명령 프롬프트 명령어 목록

명령 프롬프트는 서버의 현재 설정을 그대로 반영합니다. 예를 들어 DNS에 A 레코드를 만들면 `nslookup`과 `ping`으로 그 이름이 풀립니다.

| 명령 | 설명 |
|---|---|
| `ipconfig` | IPv4 주소, 마스크, 게이트웨이 |
| `ipconfig /all` | 호스트 이름, MAC, DHCP 사용 여부, DNS 서버, NetBIOS |
| `ipconfig /release` · `/renew` | DHCP 주소 반납·갱신 (고정 IP면 오류, 활성 DHCP 범위가 있으면 주소를 받음) |
| `ipconfig /flushdns` | DNS 확인자 캐시 비우기 |
| `ipconfig /displaydns` | DNS 확인자 캐시 보기 |
| `ipconfig /registerdns` | DNS 이름 다시 등록 |
| `ping [-n 횟수] 대상` | 에코 요청 (이름은 DNS 영역에서 확인) |
| `tracert 대상` | 경로 추적 |
| `nslookup 이름` | 이름 → IP (A, CNAME 따라감) |
| `nslookup IP` | IP → 이름 (PTR) |
| `netstat [-a] [-n]` | 연결과 수신 대기 포트 |
| `netstat -r` · `route print` | 라우팅 테이블 |
| `netstat -s` | 프로토콜 통계 |
| `arp -a` | ARP 캐시 |
| `getmac` | MAC 주소 |
| `hostname` | 컴퓨터 이름 |
| `net user` | 사용자 계정 목록 (AD 사용자 반영) |
| `net share` | 공유 목록 (만든 공유 반영) |
| `net start` | 실행 중인 서비스 |
| `systeminfo` | 시스템 정보 |
| `ver` · `help` · `cls` · `exit` | 버전, 도움말, 화면 지우기, 닫기 |

## 실제 Windows와 다른 점

- Win 키는 브라우저가 가로채지 못하므로 실행 창은 **시작 단추 오른쪽 클릭 → 실행** 으로 엽니다.
- 다시 시작은 하지 않습니다. 컴퓨터 이름 변경은 "다시 시작 대기" 상태로 남습니다.
- 실제 도메인 컨트롤러의 도메인 암호 정책은 그룹 정책(Default Domain Policy)으로 바꾸고, 로컬 보안 정책은 멤버 서버나 로컬 정책 문제에서 씁니다. 이 연습장에서는 두 도구가 **같은 설정 값**을 보여 주고 바꾸며, 바꾼 값이 바로 적용됩니다.
- MX와 CNAME의 대상은 **FQDN 전체**(예: `mail.example.com`)로 입력해야 정답으로 처리합니다.
- 새 영역 마법사의 **Active Directory에 영역 저장** 확인란은 시험 화면에 맞춰 기본으로 해제되어 있습니다. (실제 도메인 컨트롤러에서는 기본으로 선택됨)
- 다루지 않는 기능(이벤트 뷰어, 로그온 시간, MIME 형식, 오류 페이지 등)은 회색으로 표시되거나 "다루지 않습니다" 안내가 나옵니다.
- 실제 네트워크로 나가지 않습니다. `ping`, `tracert`, `nslookup` 결과는 서버 설정을 바탕으로 만든 것입니다.
